# پرونده بررسی نسخه قدیمی

گزارش تطبیق و برنامه تکمیل در این پوشه قرار دارند. خروجی ماشینی، همه ۱۳۴ قالب بررسی‌شده را نگه می‌دارد. این فایل، گزارش آزمون عملکرد یا نگاشت قطعی پایگاه داده نیست.

## بازتولید فهرست

اسکریپت با پایتون اجرا می‌شود. برای خواندن بایگانی با روش فشرده‌سازی شماره ۹۳، کتابخانه زیر لازم است؛ در محیط بررسی موجود بود و وابستگی اجرای محصول نیست.

`zstandard`

فرمان نمونه از ریشه پروژه:

```powershell
python scripts/audit_legacy_backup.py D:\Projects\GitHub\Gishow\backup_gishow.ir_2501200621 --output docs/audit/legacy-inventory.json
```

مسیر پشتیبان را متناسب با محل واقعی آن تغییر دهید. اسکریپت محتوای پشتیبان را تغییر نمی‌دهد و فایل‌های میزبانی را روی دیسک استخراج نمی‌کند. فقط قالب‌های مشخص‌شده و پشتیبان پایگاه داده را می‌خواند. خروجی، نام فایل‌ها، نام فیلدها، نشانی درخواست‌ها، ساختار مدل‌های جدید و اثر انگشت را دارد؛ اطلاعات اتصال و محتوای پایگاه داده صادر نمی‌شوند.

نشانی درخواست‌های استخراج‌شده ممکن است در کد توضیحی قالب‌ها هم باشند؛ صرف وجودشان، فعال بودن قابلیت در سایت قدیمی را اثبات نمی‌کند. بررسی مستقیم قالب و منطق قدیمی برای پذیرش لازم است.

## بازیابی جداگانه و استخراج ساختار

ابزار دوم، پشتیبان را در یک کانتینر موقت با شبکه غیرفعال و بدون انتشار درگاه بازیابی می‌کند. رمز تصادفی در هر اجرا تولید می‌شود و در گزارش یا مخزن ذخیره نمی‌شود. هیچ پایگاه داده موجودی جایگزین نمی‌شود. پس از بازیابی، پایگاه داده فقط‌خواندنی می‌شود؛ خروجی فقط ساختار، ارتباط‌ها، نمایه‌ها و شمارش تجمیعی جدول‌ها است. کانتینر متعلق به همین بررسی پس از اجرا حذف می‌شود.

فرمان اجرا از ریشه پروژه:

```powershell
python scripts/restore_legacy_schema.py D:\Projects\GitHub\Gishow\backup_gishow.ir_2501200621\databases\gishowir_EasyTicket_3\backup_dbdump_2501200621.zip --output docs/audit/legacy-database-schema.json
```

تصویر موردنیاز:

```text
mcr.microsoft.com/mssql/server:2022-latest
```

نسخه استخراج‌شده پشتیبان در پوشه زیر نگه داشته می‌شود. این پوشه از ثبت در مخزن کنار گذاشته شده و حاوی داده خصوصی است.

`.local-audit/`

ابزار برای همین دستگاه از مسیر اتصال داکر زیر استفاده می‌کند. تنظیم عمومی کاربر را تغییر نمی‌دهد.

```text
npipe:////./pipe/docker_engine
```

## ادامه گام اول

فهرست مدل‌ها و نام عملیات فایل اجرایی نیز ثبت شده است. برای بازتولید این خروجی، کتابخانه زیر لازم است. در بررسی حاضر به‌صورت محلی در پوشه خصوصی نصب شد و وابستگی اجرای محصول نیست.

`dnfile`

فرمان، در محیطی که این کتابخانه قابل واردسازی است:

```powershell
python scripts/audit_legacy_assembly.py D:\Projects\GitHub\Gishow\backup_gishow.ir_2501200621\backup_user-data_2501200621.zip --output docs/audit/legacy-assembly-inventory.json
```

این خروجی فقط نام نوع‌ها، عملیات و ویژگی‌ها را دارد. بدنه عملیات یا اطلاعات حساس استخراج نمی‌شود. نام عملیات به‌تنهایی، نشانی واقعی یا کنترل دسترسی آن را اثبات نمی‌کند.

بازیابی موفق در محیط جداگانه انجام شده و ساختار و شمارش‌های تجمیعی ثبت شده‌اند. سند نگاشت پایگاه داده، مقصد پیشنهادی همه ۲۳ جدول را مشخص می‌کند. قرارداد اولیه هر ۲۱۷ ستون و قواعد پایه تبدیل نیز ثبت شده است. مدل مقصد، تبدیل اجرایی و بررسی موارد قرنطینه هنوز باقی است. داده شخصی و فایل بازیابی‌شده وارد مخزن نشوند.

در ادامه، نگاشت پیشنهادی تمام ۲۱۷ ستون و سند قرارداد تبدیل نیز ثبت شدند. برای بازتولید بررسی‌های تجمیعی و تطبیق نام فایل‌ها، گزینه زیر به فرمان بازیابی اضافه شود. نام فایل خصوصی و مقادیر حساب‌ها در خروجی قرار نمی‌گیرند.

```powershell
--profile-output docs/audit/legacy-data-profile.json
```

فرمان بازتولید نگاشت ستون‌ها:

```powershell
python scripts/build_column_contract.py
```

برای استخراج شواهد منتخب روش تاریخ، رمز و مبلغ از فایل اجرایی، دو کتابخانه زیر لازم‌اند. شواهد فقط شامل نام عملیات و رشته‌های از پیش مجاز هستند، نه رشته‌های عمومی فایل اجرایی.

```text
dnfile
dncil
```

فرمان اجرا در محیطی که این کتابخانه‌ها قابل واردسازی هستند:

```powershell
python scripts/audit_legacy_behavior.py D:\Projects\GitHub\Gishow\backup_gishow.ir_2501200621\backup_user-data_2501200621.zip --output docs/audit/legacy-behavior-evidence.json
```
