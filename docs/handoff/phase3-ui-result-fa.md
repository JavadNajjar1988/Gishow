# نتیجه اصلاح و ادغام رابط گام سوم

خروجی شاخه اصلی با مبنای امن گام دوم ادغام شد. حساب، ثبت‌نام، بازیابی، تغییر گذرواژه، چندنقشی، نشست و دسترسی سمت سرور حفظ شدند. پنل‌های نمایشی قبلی مرجع طراحی هستند و در مسیر عملیاتی صفحه اصلی نصب نمی‌شوند. مدیریت واقعی از پنل تازه فهرست و پنل موجود حساب‌ها استفاده می‌کند.

## عملیات متصل

- دریافت، ساخت، ویرایش و حذف سالن؛ مشخصات و پلان در یک تراکنش ذخیره می‌شوند. پاسخ شامل شناسه واقعی سالن، جایگاه‌ها، صندلی‌ها و نسخه پلان است. ظرفیت از تعداد صندلی‌های ذخیره‌شده محاسبه می‌شود.
- حفظ شناسه صندلی در ویرایش مشخصات؛ رد نسخه کهنه و رد تغییر تعداد یا هویت صندلی‌های استفاده‌شده در سانس.
- دریافت برنامه‌های مجاز، ایجاد و ویرایش برنامه، پیش‌نویس و انتشار، شرح، عوامل، قوانین، زبان و توضیح بلیت. ساخت برنامه نیازمند مجوز سراسری و ویرایش نیازمند مجوز همان برنامه است.
- ساخت سانس با سالن مستقل، زمان اجرا و بازه فروش، توضیح و قیمت هر جایگاه. شناسه و موجودی از پاسخ سرور گرفته می‌شوند. مسیر سرور برای ویرایش و حذف سانس هم وجود دارد؛ کنترل‌های ویرایش و حذف سانس هنوز در رابط قرار نگرفته‌اند.
- دریافت عمومی برنامه منتشرشده، سالن هر سانس و صندلی‌های واقعی. موجودی از وضعیت پایگاه داده محاسبه می‌شود. پیش‌نویس از مسیر جزئیات قدیمی نیز نمایش داده نمی‌شود.
- واحد ذخیره مبلغ، ریال صحیح است؛ رابط تومان نمایش می‌دهد. قیمت حداقل و حداکثر از موجودی قیمت‌گذاری‌شده محاسبه می‌شوند و مقدار ساختگی تولید نمی‌شود.
- دریافت حساب با قرارداد گام دوم و ارسال سرآیند نشست موجود؛ پاسخ بدون محتوا و ارسال فرم چندبخشی در ابزار درخواست درست مدیریت می‌شوند.

شناسه رشته‌ای فقط برای سازگاری مؤلفه‌های قدیمی استفاده می‌شود؛ پیش از درخواست عدد صحیح مثبت کنترل می‌شود. شناسه موقت جایگاه در ویرایشگر تنها کلید محلی است و به سرور ارسال نمی‌شود. هر ذخیره باید پاسخ کامل سرور بگیرد.

مسیرهای عملیاتی با پیشوند جدا هستند:

```text
/api/admin/catalog/salons
/api/admin/catalog/salons/{id}
/api/admin/catalog/salons/{id}/plan
/api/admin/catalog/venue-options
/api/admin/catalog/events
/api/admin/catalog/events/{id}
/api/admin/catalog/events/{id}/run-turns
/api/admin/catalog/events/{id}/run-turns/{turn_id}
/api/catalog/events
/api/catalog/events/{id}
/api/catalog/run-turns/{id}/salon
/api/catalog/run-turns/{id}/seats
```

ویرایش سالن فعلاً مشخصات و تمام جایگاه‌ها را با نسخه فعلی می‌گیرد؛ ویرایش برنامه تمام فیلدهای فرم را می‌گیرد. این قرارداد اجرایی محدودتر از پیشنهاد ویرایش جزئی اولیه است. پلان اجراشده، ردیف و شماره صندلی هر جایگاه را ذخیره می‌کند؛ هندسه، در ورودی، دسترس‌پذیری و ترتیب جایگاه نیز ذخیره می‌شوند. ویرایش آزاد مختصات و برچسب مستقل تک‌صندلی هنوز اجرا نشده است.

## مرزهای باقی‌مانده

بارگذاری تصویر، زمان اطلاع‌رسانی، ترتیب نمایش برنامه، مختصات سانس، انتخاب مستقل واحد نمایش، ویرایش آزاد تک‌صندلی و رابط ویرایش یا حذف سانس باقی مانده‌اند. پرداخت، قفل رزرو، بلیت مهمان، تسویه و واردسازی داده قدیمی، موضوع این اصلاح نیستند. درخواست رزرو یا پرداخت سانس‌های جدید در سرور رد می‌شود؛ عملیات قدیمی جای پرداخت واقعی این قرارداد را نمی‌گیرد.

ورودی زمان تازه در فرم، میلادی با برچسب صریح و ساعت تهران است؛ پیش‌نمایش و نمایش سانس شمسی‌اند. انتخابگر ورود مستقیم شمسی هنوز اضافه نشده است. زمان ارسالی دارای اختلاف ساعت است و سرور زمان بدون اختلاف ساعت یا بازه فروش معکوس را رد می‌کند.

واحد مبلغ داده‌های قدیمی حدس زده نمی‌شود. برنامه‌های قدیمی خودکار منتشر یا تبدیل نمی‌شوند و ویرایش قرارداد قدیمی مسدود است. تغییر ساختار فقط ستون‌های تازه و مجوز ویرایش برنامه را اضافه می‌کند؛ داده مشتری، قیمت تاریخی و پشتیبان وارد نمی‌شوند.

## بررسی‌ها

نصب معمول و نصب پاک از فایل قفل موفق شدند؛ گزینه چشم‌پوشی از تعارض استفاده نشد. فایل قفل قدیمی ابزار دوم حذف شد تا مبنای نصب، فایل قفل هماهنگ با بسته‌های فعلی باشد.

```text
npm install --no-audit --no-fund: passed
npm ci --no-audit --no-fund: passed, isolated clean directory
npm run lint: passed
npm run build: passed, PWA generated
SQLite: 15 account/runtime tests + 7 catalog tests passed
PostgreSQL: result recorded in docs/phase3-verification.json
```

آزمون‌های پایگاه داده، ذخیره و دریافت مجدد، ثبات شناسه صندلی، رد نسخه کهنه، نبود مجوز، محدودیت برنامه برگزارکننده، سالن مستقل سانس، موجودی پس از فروش، رد تغییر سانس دارای صندلی فروخته‌شده، اعتبارسنجی مبلغ و تاریخ و عدم تبدیل خودکار داده قدیمی را پوشش می‌دهند. خواندن از نشست تازه پایگاه داده تأیید شد؛ راه‌اندازی دوباره سرور عملیاتی انجام نشده است.

در مرورگر، ورود با حساب موقت، ویرایش و ذخیره نام سالن، دریافت پلان واقعی سالن دوم و قیمت و موجودی آن بررسی شدند. صفحه هنگام بارگذاری اولیه و نبود برنامه دیگر به علت نبود رویداد ویژه خطا نمی‌دهد. عرض پنل در اندازه تلفن همراه بررسی و پیمایش افقی سربرگ برطرف شد.

نسخه مرورگر با پایگاه داده مستقل اجرا شد. آزمون‌های پایگاه داده سرور در ساختارهای خصوصی موقت اجرا شدند؛ داده عملیاتی و سرور اصلی داکر جایگزین نشده‌اند. رفتار بانک، هم‌زمانی پرداخت و همه امکانات پیشنهاد گام سوم تأیید نشده‌اند.

برای اجرای نسخه جدید، ابتدا تغییر ساختار زیر باید روی پایگاه داده مقصد اعمال شود و سپس سرور با کد تازه راه‌اندازی شود:

```text
python -m alembic -c backend/alembic.ini upgrade head
schema head: 0003_catalog
```

در اجرای داکر، سرویس تغییر ساختار موجود قبل از سرویس اصلی این کار را انجام می‌دهد. فایل محیط خصوصی باید مانند گام دوم فراهم باشد. برای رابط، نصب از فایل قفل و مسیر درخواست هم‌مبدأ حفظ شده است؛ سرور توسعه درخواست‌ها را به درگاه هشت‌هزار می‌فرستد مگر مقصد دیگری صریح تنظیم شود.
